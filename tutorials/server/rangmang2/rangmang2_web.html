RANGMANG 2 v2.0

RANGMANG 2 is a professional serial RGB controller based on the ATmega128 microcontroller, designed for single‑module operation. It supports 50 channels, each with 255 pixels — giving you a total of 12,750 addressable pixels per module.

🔹 Compatible with WS2812 WS2812B WS2811 WS2813 WS2815 | ✨ Ideal for cheap LED matrix, free scrolling signs, and digital advertising

Key Features

MCU: ATmega128 (11.0592 MHz)
Channels: 50 (A1–A50)
Pixels/Ch: 255 (1–255)
Total LEDs: 12,750
Protocol: UART / BT (HC‑05) 115200
Command: ARGBSE (hex encoded)
LEDs: WS2812, WS2811, WS2813, WS2815
Use: LED matrix, scrolling signs, advertising

Command Protocol — ARGBSE

Every command must end with a newline (\n or \r\n). Only uppercase letters are accepted. No spaces.

LetterMeaningRangeDescription
AChannel Address1 – 50Channel number
RRed0 – 255Red intensity
GGreen0 – 255Green intensity
BBlue0 – 255Blue intensity
SStart0 – 255First pixel index
EEnd1 – 255Last pixel index

ARGBSE Data Encoding — Hex Transmission

To minimize character payload, each variable is converted to 2-character hexadecimal before transmission. The microcontroller then decodes each byte and executes the command.

VariableMeaningRangeHex RangeChars
AChannel Address1 – 5001 – 322
RRed0 – 25500 – FF2
GGreen0 – 25500 – FF2
BBlue0 – 25500 – FF2
SStart0 – 25500 – FF2
EEnd1 – 25501 – FF2

Total per command: 6 variables × 2 hex chars = 12 characters

Packet Structure — Multi-Command Transmission

Commands are transmitted in packets of up to 20 (updated from 10). Each packet can contain 1 to 20 commands, processed in order.

Packet Rules

  • Up to 20 commands can be sent in one transmission
  • If fewer than 20, only available commands are sent
  • Even a single command is valid and processed
  • Commands are processed in the order received

🧰 RANGMANG 2 Web Tool — User Guide

The RANGMANG 2 Web Tool (available via the Web Simulator) is a companion application that converts images and pixel designs into hex‑encoded ARGBSE commands for direct transmission to the ATmega128 controller. Perfect for creating cheap LED matrix displays, free scrolling signs, and digital advertising using WS2812 / WS2811 / WS2813 / WS2815 strips.

1. How to Use the Web Tool

  • Upload Images: Click “Choose Images” or drag & drop one or more images onto the canvas.
  • Adjust Settings: Set Channels (1–50) and Pixels per Channel (1–255) to match your LED layout.
  • Copy & Send: Use “Copy” to copy the hex string to your clipboard, or send it directly via SoifGo.

2. Packet Size — 20 Commands per Transmission

Unlike the earlier 10‑command limit, the Web Tool now groups up to 20 commands into a single packet for better efficiency. This means:

  • Each packet contains up to 20 hex commands (12 chars each = 240 characters).
  • If you have fewer than 20, only the available commands are sent.
  • Even a single command is valid and processed correctly.
  • Commands are executed in the exact order they appear.

3. Refresh Toggle — wait vs WAIT

The “Refresh” checkbox controls the case of the wait keyword that is inserted before each frame in the output.

  • Enabled (Refresh ON): Output uses WAIT=... (uppercase). → The microcontroller clears the screen before drawing the next frame.
  • Disabled (Refresh OFF): Output uses wait=... (lowercase). → The microcontroller does NOT clear the screen; the next frame overlays on the previous one.

4. Wait Value — Inter‑Frame Delay

Each frame in the Web Tool has a wait value (in milliseconds) that defines the delay after that frame is displayed.

  • Default: wait = 0 (no delay).
  • To set: Use the “Wait (S)” input box and click “Apply” to assign a delay to the current frame.
  • If no inter‑frame delay is needed, leave it at 0 — the frame will be displayed immediately and the next frame will follow without pause.

5. SoifGo Integration — Custom Wait

In the SoifGo application (on your smartphone), you have an additional option to control how wait commands are handled:

  • Go to SoifGo Settings → Note Out.
  • Find the Custom Wait toggle.
  • Enable → SoifGo will respect and forward the wait / WAIT values exactly as generated by the Web Tool.
  • Disable → SoifGo will ignore the wait lines and send only the hex commands (useful if you want to manage timing manually).

6. Quick Tips

  • Output not updating? Make sure you have at least one frame (from images or the Pixel Editor) and click “Process All”.
  • Microcontroller not responding? Check baud rate (115200) and ensure your serial connection is active.
  • Colors look wrong? Toggle the “RBG (WS2811)” checkbox to swap Green and Blue channels if you are using WS2811/WS2812 LEDs.
  • Need to clear everything? Use the “Clear” button to reset all frames and images.
